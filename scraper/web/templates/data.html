Data

The master set and its ledger, bringing images and annotations in from elsewhere, and getting annotations out. Annotating itself is on the Annotate page.

Master set

One copy of every kept image, in one home: data/images/<family>/. Keep on the Review page moves an image there. The ledger (data/ledger.db) remembers every image ever seen and what was decided, so a rejected picture never comes back from any source, and an image already here is recorded as another source instead of being stored twice. It lives in data/, so it survives a wipe and moves with the folder.

CheckImages

Add images from an outside source

Copies a folder of images into the inbox (the originals stay where they are). Each one gets the same checks as a scraped download: rejected before is set aside, already in the master set is recorded as another source. New ones wait on the Review page, unless you mark them as already reviewed. Every image needs a family (one for all, a subfolder per family, or a manifest column) and a license; an image without a license isn't added. 


  


  

    
Import

    

      Adds a data folder's images (images/) and their answers (annotations.csv, or
      annotations/<annotator>.csv) to the database, so they join the scraped images in one
      pool, using the ledger for each image's family, license and any earlier rejection (that's how the database
      is rebuilt after a wipe). When an imported image is the same file as a scraped one, the imported copy is
      kept and takes over the scraped copy's license record; the scraped copy is set aside. Rows the old tool's CSV wrote into the wrong columns are left out, so those images come
      up on the Annotate page to be labeled again, unless the CSV is fixed first (below).
    

    

      
      
      
    

    


    

      Only an annotations CSV
      

        For an old-tool CSV (annotatedInfo.csv) whose images are already in the database, like scraped ones:
        rows are matched to images by file name and their answers kept as written, under the annotator name
        below. Rows that match no image, or whose values look like they're in the wrong column, are skipped
        and listed in a review file instead of guessed at.
      

      

        
        

          
          
        

        
        
      

      

    


    

      Fix an old CSV's shifted rows
      

        The old tool sometimes wrote a row's answers under the wrong headers (solar panel answers under
        Manufacturer, for one), and those rows are left out of imports and training. This writes a fixed
        copy of the CSV with the rows that match a known mix-up put back in the right columns. The original
        file is never changed, rows that don't look shifted are never touched, and a row no known fix
        explains is left as it was and listed for a person to look at.
      

      

        
        

          
          
        

        
        
      

      

    

  


  

    
Export annotations

    

      Writes every saved annotation to a CSV: one row per image and annotator, columns in the current
      attribute order (same layout as the old tool's annotatedInfo.csv, plus family and provenance columns at
      the end). Rebuilt from the database each time.
